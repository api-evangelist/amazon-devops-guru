<p><a href="https://aws.amazon.com/devops-guru/">Amazon DevOps Guru</a> is a fully managed AIOps service that uses machine learning (ML) to quickly identify when applications are behaving outside of their normal operating patterns and generates insights from its findings. These insights generated by Amazon DevOps Guru can be used to alert on-call teams to react to anomalies for mission critical workloads. Various customers already utilize Incident management systems like <a href="https://www.servicenow.com/">ServiceNow</a> to identify, analyze and resolve critical incidents which could impact business operations. ServiceNow is an IT Service Management (ITSM) platform that enables enterprise organizations to improve operational efficiencies. Among its products is Incident Management which provides a single pane view to customers and allows customers restore services and resolve issues quickly.</p> 
<p>This blog post will show you how to integrate Amazon DevOps Guru insights with ServiceNow to automatically create and manage Incidents. We will demonstrate how an insight generated by Amazon DevOps Guru for an anomaly can automatically create a ServiceNow Incident, update the incident when there are new anomalies or recommendations from Amazon DevOps Guru, and close the ServiceNow Incident once the insight is resolved by Amazon DevOps Guru.</p> 
<h2><strong>Overview of solution</strong></h2> 
<p>This solution uses a combination of event driven architecture and Serverless technologies, to integrate DevOps Guru insights with ServiceNow. When an Amazon DevOps Guru insight is created, an <a href="https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rules.html">Amazon EventBridge rule</a> is used to capture the insight as an event and routed to an <a href="https://aws.amazon.com/lambda/">AWS Lambda Function</a> target. The lambda function interacts with ServiceNow using a REST API to create, update and close an incident for corresponding DevOps Guru events captured by EventBridge.</p> 
<p>The EventBridge rule can be customized to capture all DevOps Guru insights or narrowed down to specific insights. In this blog, we will be capturing all DevOps Guru insights and will be performing actions on ServiceNow for the below DevOps Guru events:</p> 
<ul> 
 <li>DevOps Guru New Insight Open</li> 
 <li>DevOps Guru New Anomaly Association</li> 
 <li>DevOps Guru Insight Severity Upgraded</li> 
 <li>DevOps Guru New Recommendation Created</li> 
 <li>DevOps Guru Insight Closed <p></p>

<h2>Solution Implementation Steps</h2> 
<h3>Prerequisites</h3> 
<p>Before you deploy the solution and proceed with this walkthrough, you should have the following prerequisites:</p> 
<ul> 
 <li>Gather the hostname for your ServiceNow cloud instance. If you do not have a ServiceNow instance, you can request a developer instance through the <a href="https://developer.servicenow.com/dev.do">ServiceNow Developer page</a>.</li> 
 <li>Gather the credentials of a ServiceNow user who has permissions to make REST API calls to ServiceNow, specifically to the Table API. If you don’t have a user provisioned, you can create one by following the steps in <a href="https://docs.servicenow.com/bundle/madrid-application-development/page/integrate/inbound-rest/concept/c_GettingStartedWithREST.html">Getting started with the REST API</a> in the ServiceNow documentation.</li> 
 <li>Create a secret in Secrets Manager to store the ServiceNow credentials created in previous step. You can choose any name for the secret but it should have two key/value pairs, one for username and other for password.</li> 
 <li>Enable DevOps Guru for your applications by following these <a href="https://docs.aws.amazon.com/devops-guru/latest/userguide/getting-started-enable-service.html">steps</a> or you can follow this <a href="https://aws.amazon.com/blogs/devops/gaining-operational-insights-with-aiops-using-amazon-devops-guru/">blog</a> to deploy a sample serverless application that can be used to generate DevOps Guru insights for anomalies detected in the application.</li> 
 <li>Install and set up SAM CLI – <a href="https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/serverless-sam-cli-install.html">Install the SAM CLI</a></li> 
 <li>Download and set up Java. The version should be matching to the runtime that you defined in the SAM template.yaml Serverless function configuration – <a href="http://www.oracle.com/technetwork/java/javase/downloads/jdk8-downloads-2133151.html">Install the Java SE Development Kit 11</a></li> 
 <li>Maven – <a href="https://maven.apache.org/install.html">Install Maven</a></li> 
 <li>Docker – <a href="https://hub.docker.com/search/?type=edition&amp;offering=community">Install Docker community edition</a></li> 
</ul> 
<p>You have two options to deploy this solution, one options is to deploy from the AWS Serverless Repository and other from the Command Line Interface (CLI).</p>

<h3>Option 2: Build and Deploy sample ServiceNow Connector App using AWS SAM Command Line Interface</h3> 
<p>As you have seen above, you can directly deploy the sample serverless application from the Serverless Repository with one click deployment. Alternatively, you can choose to clone the github source repository and deploy using the SAM CLI from your terminal.</p> 
<p>The Serverless Application Model Command Line Interface (SAM CLI) is an extension of the AWS CLI that adds functionality for building and testing serverless applications. The CLI provides commands that enable you to verify that AWS SAM template files are written according to the specification, invoke Lambda functions locally, step-through debug Lambda functions, package and deploy serverless applications to the AWS Cloud, and so on. For details about how to use the AWS SAM CLI, including the full AWS SAM CLI Command Reference, see <a href="https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/serverless-sam-reference.html#serverless-sam-cli">AWS SAM reference – AWS Serverless Application Model</a>.</p> 
<p>Before you proceed, make sure you have completed the Prerequisites section in the beginning which should set up the AWS SAM CLI, Maven and Java on your local terminal. You also need to install and set up Docker to run your functions in an Amazon Linux environment that matches Lambda.</p> 
<p>Follow the steps below to build and deploy this serverless application using AWS SAM CLI in your AWS account:</p> 
<ul> 
 <li>Clone the source code from the github repo</li> 
</ul> 
<pre><code class="lang-bash">$ git clone <a href="https://github.com/aws-samples/amazon-devops-guru-connector-servicenow.git">https://github.com/aws-samples/amazon-devops-guru-connector-servicenow.git</a></code></pre> 
<ul> 
 <li>Before you build the resources defined in the SAM template, you can use the below validate command which will run cfn-lint validations on your SAM JSON/YAML template</li> 
</ul> 
<pre><code class="lang-bash">$ sam validate –-lint --template template.yaml</code></pre> 
<p>3.&nbsp;&nbsp;&nbsp;&nbsp; Build the application with SAM CLI</p> 
<pre><code class="lang-bash">$ cd amazon-devops-guru-connector-servicenow
$ sam build</code></pre>

<pre><code class="lang-bash">$ sam deploy –-guided</code></pre>

<h2>Conclusion</h2> 
<p>This blog post showcased how DevOps Guru continuously monitor resources in a particular region in your AWS account and automatically detects operational issues, predicts impending resource exhaustion, details likely cause, and recommends remediation actions. This post described a custom solution using serverless integration pattern with AWS Lambda and Amazon EventBridge which enabled integration of the DevOps Guru insights with customer’s most popular ITSM and Change management tool ServiceNow thus streamlining the Service Management governance and oversight over AWS services. Using this solution helps Customer’s with ServiceNow to improve their operational efficiencies, and get customized insights and real time incident alerts and management directly from DevOps Guru which provides a single pane of glass to restore services and systems quickly.</p> 
<p>This solution was created to help customers who already use ServiceNow Incident Management, if you are already using Incident Manager from AWS Systems Manager, check out how that works with Amazon DevOps Guru <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/quick-setup-devops.html">here.</a></p>
